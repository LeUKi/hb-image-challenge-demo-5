# 图片挑战 · hb-image-challenge

一个可复用的图片挑战判定器和作者自建服务。玩家上传图片，AI 判断它与挑战描述的匹配度；分数落在作者设定的区间，再由红包站判定器核验和发奖。

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/LeUKi/hb-image-challenge)

[使用图片挑战发红包](https://hb.lafi.sh/new?judge=0f06222c-e8b2-4683-89d9-ae8900e66cea) · [判定器代码](judge/judge.js) · [配套测试](judge/tests.json)

先部署自己的 Cloudflare 服务，应用参数只需填写 `OWNER_ID`（你的 LINUX DO 数字用户 ID）。发红包时填入服务根地址和挑战规则。**本仓库新增的多次奖励需要新版 Worker 和新版红包站判定器配套；公共判定器不会随 GitHub 推送自动更新。**请先确认所用判定器的表单已出现“多次奖励”开关。

## 部署到自己的 Cloudflare

1. 点击上面的按钮，登录 Cloudflare 并连接自己的 GitHub。模板会声明 AI、R2 和 D1 绑定，由官方部署流程创建、绑定资源。首次使用 R2 时可能需要先完成 Cloudflare 的账户开通流程。
2. 只需填写一个应用参数：`OWNER_ID`，值为自己的 **LINUX DO 数字用户 ID**。服务默认连接 `https://hb.lafi.sh`，空 ID 的服务拒绝上传。
3. 如果 Cloudflare 默认勾选了 **启用预览构建（Enable Preview Builds）**，请取消；**使用 Cloudflare Access 保护**无需启用。高级设置里的构建和部署命令保持默认，然后开始部署。
4. 点击[使用图片挑战发红包](https://hb.lafi.sh/new?judge=0f06222c-e8b2-4683-89d9-ae8900e66cea)，已选好图片挑战判定器。在“服务地址”中填入部署得到的根地址，例如 `https://你的服务.workers.dev/`，再设置图片要求、评分区间、每人次数（1–10，默认 3）和奖励。网页标题直接使用红包标题。

模板只声明 `OWNER_ID` 这一个普通应用变量，不要求填写 AI Token、R2 密钥或站点地址。AI、R2、D1 由部署流程创建并绑定；部署命令会构建 SSR、发布 Worker 并执行数据库迁移。`database_id` 的全零值是模板占位，官方部署流程会替换为实际资源 ID。

模板显式设置了 `preview_urls: false`，关闭版本预览地址。但 Cloudflare 的“启用预览构建”是平台的分支构建开关，当前没有公开的 Deploy Button 模板设置可将它默认取消；上面的第 3 步仍需在 Cloudflare 表单中完成。二者不能互相替代。官方说明：[部署按钮](https://developers.cloudflare.com/workers/platform/deploy-buttons/)、[预览构建开关](https://developers.cloudflare.com/workers/ci-cd/builds/build-branches/#configure-preview-builds)。

正式的 `workers.dev` 地址已通过 `workers_dev: true` 显式开启，构建后的部署配置也保留此值，正常完成部署后无需逐个手动启用。Cloudflare 的 **Settings → Domains & Routes** 中，版本预览地址关闭是预期行为；若正式 `workers.dev` 一行仍显示禁用，请检查这次部署是否成功、采用的提交和配置是否正确。首次使用 Workers 的账户可能还需按提示注册账户级 `workers.dev` 子域名。详见 [workers.dev 官方说明](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)。

本地配置示例放在 `docs/local-worker-config.example`。仅开发联调需要时，可在本地 `.dev.vars` 用 `HB_SITE` 指向官方模拟器；它不在默认部署表单中展示。不要为普通变量添加根目录 `.dev.vars.example` 或 `.env.example` 声明，否则 Deploy to Cloudflare 会将同名变量再次识别为 secrets。

通过 CLI 部署时，需要先创建资源并填写数据库 ID：

```sh
npx wrangler login
npx wrangler r2 bucket create hb-image-challenge-images
npx wrangler d1 create hb-image-challenge
# 将命令返回的真实 database_id 填入 wrangler.jsonc，并设置 OWNER_ID。
npm run deploy
```

上面的发红包链接使用已发布的公共判定器。需要自行修改和发布判定器时，使用 [judge/judge.js](judge/judge.js) 和 [judge/tests.json](judge/tests.json)；更新 Cloudflare 服务不会自动更新红包站保存的判定器代码。这个仓库的代码准备和本地验证，不代表生产 AI、R2、红包领取或官方部署按钮已经端到端实测。

## 技术栈

- **TanStack Start + Router**：React 服务端渲染、文件路由，Cloudflare Workers 官方 Vite adapter。
- **TanStack Query**：服务端数据缓存与上传 mutation；**TanStack Form**：类型安全表单。
- **Tailwind CSS 4**：简约响应式界面；**Motion**：遵循减少动画偏好；**Jotai**：交互状态，每次 SSR 请求隔离。
- **Workers AI**：固定 `@cf/cloudflare/clef-flash` 模型，使用 AI binding。
- **R2**：私有图片存储，所有部署均包含；红包作者可按红包关闭实际图片保存。
- **D1**：结果、一次性 nonce、幂等键和原子次数限制。

不需要作者把 Cloudflare AI Token 或 R2 密钥交给判定器作者。每位红包作者把整套服务部署到自己的 Cloudflare 账户；自己的用量、图片和数据库由自己管理。

## 作者参数与奖励

参数由红包站原生表单生成；玩家网页只提供浏览设置。

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| 服务地址 | 必填 | 你自己部署的 Worker 根地址 |
| 图片要求 | 这张图片里有一只猫 | 模型判断的特征，与红包标题分开 |
| 最低 / 最高匹配度 | 70 / 100% | 包含上下限的合格区间 |
| 每人最多上传次数 | 3 | 可设置 1–10 次 |
| 多次奖励 | 开启 | 每张合格图片分别计奖，最终统一领取；关闭时首次通过即领取 |
| 按评分发奖 | 关闭 | 关闭时，合格即发最高奖励 |
| 最低奖励 | 0.01 LDC | 每张图片的最低奖励，开启按评分发奖时对应最低合格分 |
| 最高奖励 | 1.00 LDC | 每张图片的最高奖励；关闭按评分发奖时统一发此金额 |
| 保存玩家图片 | 开启 | 保存到本作者的私有 R2；关闭后保留评分记录 |

开启按评分发奖后，评分区间会线性对应到最低、最高奖励。例如设定 **70–80%**、**1–10 LDC**：70% 得 1 LDC，75% 得 5.50 LDC，80% 得 10 LDC。金额按整数分向下取整；区间外无奖；评分上下限相同时，达标发最高奖励。实际发放不超过剩余奖池，玩家提交前看到的是预计金额。

红包站当前不支持参数条件隐藏，最低奖励始终显示，关闭按评分发奖时不生效。无需选择额外的曲线、倍率或高级模式。

### 多张图片分别计奖

开启“多次奖励”后，玩家每张不同图片分别上传、评分和提交。合格的图片各自计算奖励，未合格图片不影响此前已累计的金额。例如上面的动态奖励规则中，一张 75% 图片累计 5.50 LDC，再提交一张 72% 图片累计 2.80 LDC，工作区显示**累计待领取 8.30 LDC**，玩家仍可继续上传。

红包站目前是**多次记奖、每人最终只结算一次**。玩家点击“结算并领取”并确认，结束本轮参与后统一领取累计金额；剩余上传机会和未提交评分不再计奖。也可直接在红包站输入 `结算`，该操作无需连接图片服务，服务暂时不可用也不会困住已有奖励。上传次数用完、全部已评分结果均已提交且没有图片处理中时自动结算；活动截止、结束或奖池分配完也由平台统一结算。最后一次上传失败或命中重复图片时，仍可主动结算。

同一结果只能计奖一次。刷新后从本人私有记录恢复所有已提交图片及各图真实金额；尚未最终领取时不提前解锁他人的合格作品。结算或领取后关闭上传，刷新也不会重新开放。提交结果或结算出现 `unconfirmed` 时只核对记录，不自动重试。

新判定器的表单默认开启此功能；已存在且缺少该参数的红包继续使用一次奖励规则。升级不需要新增数据库迁移，但需要同时更新 Worker 并在红包站发布 [judge/judge.js](judge/judge.js) 的新版；仅推送仓库或更新 Worker 不会改变已保存的公共判定器与旧红包参数。

## 匿名画廊

玩家页采用紧凑双栏，手机上下排列，没有顶栏。设置、玩法和大图以弹窗打开，支持点击空白和 Esc 关闭。页面与弹窗隐藏滚动条，保留滚轮、触控板和键盘滚动，打开弹窗不改变背景宽度。作品按最新优先的瀑布流排列，新图直接自动显示；已有作品保留分栏，下方阅读时维持滚动位置，不做飞入或重排动画。

评分完成后清空上传框，自动打开与画廊共用的图片查看器。查看器显示匹配评分、NSFW 评分、目标区间、模型和图片尺寸；本人结果还可在参与状态允许时查看预计奖励并提交，已计奖图片展示实际记账金额。关闭后可以从“查看本次结果”或画廊重新打开；选择另一张图片不会丢失之前本人作品的提交入口，提交始终对应查看器中选中的结果。最终领取后不能继续参与。刷新恢复结果时不会自动弹窗。关闭图片保存时，当前页面仍可查看刚上传图片的本地预览，刷新后仅保留评分。

卡片显示图片、评分和心形点赞数：合格分数字体为绿色，其余为白色。参与前可见本人作品和他人的区间外评分；本人成功领取或活动结束后，可看本轮所有已同意共享的作品。列表和图片接口都执行这个权限规则。图库不返回或显示昵称、头像、用户编号和匿名代号；图片本身可能包含的个人信息不会被自动消除。

新上传会在操作旁告知画廊展示规则。升级前按私密规则保存的图片继续保持原权限，活动结束也不会自动公开。关闭图片保存时，画廊只展示分数。已领取、已结算、活动结束、机会用完和提交待确认均会恢复对应状态，刷新不会重新开放已完成玩家的上传界面。

同一红包内，所有玩家共享图片文件 SHA-256 的去重占位。重复上传也消耗一次机会，但不会再次调用 AI、写入 R2 或新增作品；相同幂等请求的重试不再扣次。只在真正命中重复时显示简短提示，玩家页面不额外增加去重说明。确定的处理失败会释放原占位；仅按原文件内容去重，不保证识别压缩、裁剪或重新编码后的相似图片。已有服务升级需应用 `0004_image_dedup.sql`，默认部署命令包含迁移。

新评分固定使用 **Clef Flash · Cloudflare Workers AI**。服务端在同次调用中分别提出作者的匹配问题和固定 NSFW 问题；作者的图片要求不能替换固定的安全问题。NSFW 分数达到 50% 或缺失安全分时，默认显示写有 **NSFW** 的模糊遮罩，点击可单张查看；浏览设置可在本浏览器关闭模糊。这个启发式分数没有经过准确率验证，遮罩也不替代服务端图片权限。

从 Clef Omni 切换到 Flash 这一项只需更新并重新部署 Worker；启用多次奖励则还需要新版判定器。每次新评分会记录实际模型，历史评分继续显示 Clef Omni，不会重新推理。Flash 与 Omni 的实际分数分布尚未对比，已有评分区间需结合自己的图片检查。

图库优先随红包站 SDK 的红包、本人状态与私人结果变更合并刷新；初次进入、回到前台和本人的评分完成后立即刷新。页面可见时每 60 秒兜底拉取，隐藏时停止，无需 Durable Objects。

### 连续点赞

可以反复点击心形；数量立即更新，按钮使用轻量 Motion 反馈。点赞不改变评分、奖励或作品排序，也不重新下载已加载的图片。

- 第一次点击后等待 30 秒，将多张图片的点赞合成一批上传；继续点击不会推迟原定时间。有待同步数据时，每 30 秒最多发出一个新批次，能够与画廊刷新合并时共用一次 POST。
- 同步响应同时返回最新点赞数。没有本地点赞时，随画廊的 60 秒前台轮询、红包动态或手动刷新获取其他人的点赞；页面隐藏时暂停定时同步，回到前台再继续。
- 浏览器允许会话存储时，当前标签页按红包和已验证的数字用户 ID 暂存待同步数据，刷新后恢复。服务器已经保存但响应丢失时，只读查询批次回执；重试同一批也不会重复加数。关闭标签页前尚未同步的点赞不保证保存，不依赖退出页面时强行发请求。
- 服务端对同一红包的同一真实玩家原子执行 30 秒门限；多个标签页共用这一门限。单批最多 50 张图、每张最多 1,000 次，超出的正常点击保留到后续批次。只能给自己有权查看的作品点赞，返回的数据保持匿名。

这套控制减少正常连点的请求量，以及过频请求造成的后续写入；直接请求接口仍会到达 Worker，需要在边缘拦截时应另行配置适用于部署域名的规则。

已有部署需要应用新增的 D1 迁移 `0003_gallery_likes.sql`。默认 `npm run deploy` 已包含迁移步骤；使用自定义部署命令时，补执行 `npx wrangler d1 migrations apply DB --remote`。点赞不修改判定器代码，无需为此重新发布红包站判定器。

## 官方模拟器体验

需要 Node.js **22.12+**、已安装依赖，以及本机可运行 workerd。以下命令不要求 Cloudflare 登录或生产凭据：

```sh
npm ci
npm run simulator
```

打开终端给出的地址，默认是 **http://127.0.0.1:8860/?layout=multi&players=3&accept=1&open=1**。这是未改动的官方模拟器，运行本仓库的真实判定器与构建后的 SSR 页面；上传和图片读取使用真实产品处理函数、本地 D1 / R2，以及官方模拟器签发的身份和判定令牌。

模拟器预置无害插画，包含普通、合格和 NSFW 遮罩演示。页面明确标注模拟评分；AI 使用本地替身，**不调用真实模型、不发真实奖励**。玩家小明的上传依次得到 35%、75%、91%、72%、57% 演示分数，本轮 70–80% 合格、每图奖励 1–10 LDC，多次奖励已开启。提交 75% 和 72% 两张图片后累计 8.30 模拟 LDC，可继续上传或主动结算。可以上传自己的不同图片，或下载尚未被样例使用的 `http://127.0.0.1:5173/__demo/image?n=8` 至 `n=11` 演示图。

服务端必须读取的公开活动接口由仅本地脚本补齐，生产鉴权不放宽，也没有部署版调试入口。所有模拟数据在停止并重启此命令后清空；官方模拟器“重新开始”只重置判定器，完整重置请重启命令。若端口被占用，可用 `SIMULATOR_PORT=8870 npm run simulator` 改变模拟器端口；5173 / 5175 也需空闲。

已构建后可用 `npm run simulator:start` 直接重启。`npm run check` 执行静态与单元验证；`node scripts/simulator-api-smoke.mjs` 和 `node scripts/simulator-smoke.mjs` 验证本地完整流程，运行后请重启以恢复可体验的初始状态。

## 数据流与边界

1. 附带网页通过 `hb.identity({ nonce })` 获取签名 JWT。
2. 浏览器把原始图片传到同源 Worker，Worker 验证 JWT、公钥、issuer、audience、到期时间、作者、红包、玩家和一次性 nonce。
3. Worker 从红包站公开接口获取真实挑战规则。客户端不能提高作者的尝试上限或替换挑战描述。
4. D1 原子预占尝试次数，按“红包 + 玩家”最多 10 次。同一幂等键绑定图片哈希，重试不重复调用 AI。
5. R2 保存与 AI 推理并行进行，只有所需步骤都成功、真实结果持久化后才返回结果编号。
6. 网页把短结果编号交给 `hb.submit()`；判定器用 `X-Hb-Token` 请求 Worker 核验，核对玩家、红包和挑战参数后决定奖励。
7. 多次模式下，判定器将逐图结果和实际记奖金额保存在玩家私有状态，累加到平台 `pending`；主动或自动结算后才统一付款。页面的“结算并领取”提交固定 `结算` 指令，判定器仅使用平台自己的待结算金额。

已接受并开始处理的失败请求会保守计入一次尝试，因为 AI 调用可能已产生用量。查询已保存结果、幂等重放不会新增推理。`unconfirmed` 的红包提交不自动重试。

图片支持 JPEG、PNG、WebP，最多 **4 MiB、1600 万像素**。服务端验证实际文件头和尺寸；模型接收嵌入图片，不读取图片外链。R2 默认不公开，读取图片同样校验玩家身份。
